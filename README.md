# 电子提单控制权交接

保证电子提单控制权、运输事实和跨境支付条件始终一致。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括进出口企业、承运人、贸易融资银行、提单平台运营方。

资料所依据的领域事实如下：

- 跨境服务平台联通电子提单平台
- 业务目标是统一信息流、资金流和单据流
- 贸易履约条件达到后才执行定向支付
- 货权已转移而承运人事件晚到时，旧持有人仍可能触发放款或重复背书，危害高于跨境到账慢

围绕每份电子提单，签发方、当前持有人、背书序列、货物批次、运输节点、质押状态和支付条件都要经过校验。每次转让由双方签名，并作为不可覆盖的事件生效；承运人事件晚到不改变已生效的控制权归属。

可见性按角色划分：银行只读取履约所需证明，贸易方随时看得到自己的权利和待办。

承运人离线回补、改单、拆单、合单、质押解除、争议冻结和重复回调都属于必须容纳的异常事件，处理这些事件不得破坏唯一现状与完整历史。审计人员应能从任一支付动作确认当时的控制权、运输事实和异常补偿结果。

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实、约束，以及每份提单校验项、转让规则、可见性规则、异常事件和审计要求。运行项目自带测试即可检查这些基础资料能够稳定读取。仓库不保存账号、密钥、连接串或真实身份信息。
